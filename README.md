# Kantra

Мессенджер со сквозным шифрованием, который разворачивается на своём сервере.
Привычный интерфейс в духе Telegram: чаты, группы, звонки, медиа, несколько устройств.
Все сообщения, файлы и звонки шифруются на устройствах по протоколу
[MLS](https://www.rfc-editor.org/rfc/rfc9420) (RFC 9420). Сервер видит только шифротекст
и пересылает его, но прочитать не может.

Клиенты есть для Windows, macOS, Linux, Android и iPhone, а также веб-вариант. Сервер —
набор сервисов на Go в Docker; поднять его на своём VPS — **[DEPLOY.md](DEPLOY.md)**.

> Проект учебный: независимого аудита безопасности не было (см. «Ограничения»).

## Возможности

**Чаты**
- Личные чаты по `@username` и группы; закреплённые чаты, режим «без звука», поиск людей.
- Ответы, пересылка, редактирование, удаление у себя или у всех, реакции, ✓/✓✓ прочтения,
  «печатает…».
- Форматирование текста, спойлеры, упоминания, превью ссылок, опросы, закреплённые
  сообщения, поиск по чату, выделение нескольких сообщений.
- Отложенные сообщения и отправка без звука.
- Отправка без сети: сообщение ждёт с часиками и уходит само, когда появится соединение.
- Ссылки-приглашения в группы, описание и фото группы, системные сообщения
  («добавил», «вышел»…), чёрный список, «в сети / был(а)».

**Медиа**
- Фото и видео прямо в ленте (с размытым превью до загрузки), альбомы, файлы до 64 МБ.
- Голосовые сообщения и видеосообщения-«кружочки».
- Эмодзи-клавиатура, сохранённые GIF и стикеры.
- Медиа чата по вкладкам, сохранение в галерею / «Загрузки».

**Звонки**
- Аудио- и видеозвонки один на один и в группах, демонстрация экрана.
- Шифрование WebRTC (DTLS-SRTP), сигнализация звонка — внутри MLS; TURN-сервер в комплекте.

**Устройства и безопасность**
- Несколько устройств на аккаунт: новое подтверждается кодом на старом и сразу получает
  чаты и историю.
- Ключ восстановления из 12 слов — если потеряны все устройства.
- Сверка ключей шифрования собеседников (отпечатки), предупреждение о смене ключа.
- Несколько аккаунтов в одном приложении, код-пароль на вход, светлая и тёмная тема.

**Уведомления без Google и Apple**
- Приложение само держит одно соединение с вашим сервером: ни FCM, ни APNs не участвуют.
- Android — фоновый сервис; iPhone — режим «Работать в фоне»; ПК — системные уведомления и трей.

**Обновления**
- Каждая версия публикуется в [Releases](../../releases): ПК обновляется сам (ставится при
  перезапуске), Android — через установщик системы, iPhone — через AltStore / SideStore.

## Установка

Скачайте файл для своей платформы из последнего [релиза](../../releases/latest):

| Платформа | Файл | Заметки |
|---|---|---|
| Windows | `Kantra-windows-amd64.exe` | дальше обновляется сам |
| macOS (Apple Silicon) | `Kantra-macos-arm64.zip` | дальше обновляется сам |
| Linux | `Kantra-linux-amd64` | дальше обновляется сам |
| Android | `Kantra-android-arm64.apk` | при первом обновлении разрешите «Установку из этого источника» |
| iPhone | источник `…/releases/latest/download/altstore.json` | добавьте в AltStore / SideStore |

При первом запуске укажите адрес своего сервера, зарегистрируйтесь или войдите. Вход с
нового устройства подтверждается на уже подключённом.

## Как это работает

```
 устройство A ──┐                                    ┌── устройство B
 (MLS-ключи,    │   HTTPS / HTTP/3 (QUIC)            │   (MLS-ключи,
  SQLite)       ├──►  Caddy  ──►  auth · directory ◄─┤    SQLite)
                │              delivery · history    │
                │              media                 │
                └──── WebTransport / WebSocket ──────┘
                      Postgres (метаданные), MinIO (шифротекст)
```

- **Шифрование.** Каждая переписка — MLS-группа, каждое устройство — её участник со своими
  ключами. Криптография — библиотека [`mls-rs`](https://github.com/awslabs/mls-rs) (Rust),
  подключённая к Go через cgo; свой криптографии в проекте нет. Ключи и расшифрованные
  сообщения хранятся только на устройствах.
- **Сервер** лишь маршрутизирует зашифрованные сообщения и следит за порядком изменений
  состава групп (эпох MLS). Он знает, кто с кем в группе и когда активен, но не содержимое.
- **Доставка.** Постоянное соединение (WebTransport поверх QUIC, при недоступности —
  WebSocket) приносит сообщения мгновенно; неподтверждённое передоставляется после
  переподключения. HTTP-запросы идут по HTTP/3 с откатом на HTTP/2. Смена сети (Wi-Fi ↔
  мобильная) переживается без потери соединения.
- **Медиа.** Файл шифруется на устройстве случайным ключом и загружается шифротекстом;
  ключ уходит собеседникам внутри MLS-сообщения. Загруженное кэшируется на устройстве.
- **История и новые устройства.** Ключ истории аккаунта есть только на ваших устройствах.
  Они непрерывно выгружают зашифрованный бэкап переписки; новое устройство получает этот ключ
  после подтверждения, восстанавливает историю и само вступает во все чаты (MLS External
  Commit). Недостающее досылают онлайн-участники.
- **Ключ восстановления** (12 слов) хранит ключ истории в зашифрованном виде на сервере; без
  фразы сервер его прочитать не может.
- **Сверка ключей.** Клиент запоминает ключ каждого устройства собеседника; смена ключа
  блокирует отправку до проверки — защита от подмены сервером.

## Ограничения

- Независимого аудита безопасности не было.
- Identity устройства не заверена доверенной стороной: при самом первом контакте
  злонамеренный сервер теоретически может подменить ключ. Защита — сверка отпечатков.
- Локальная база на устройстве не зашифрована (защищайте устройство паролем ОС; в приложении
  есть код-пароль на вход).
- Сообщения, досланные другим участником для нового устройства, подписаны переславшим, а не
  исходным автором.
- iPhone получает уведомления, только пока приложение работает (в фоне или открыто):
  смахнутое из списка приложение до следующего запуска молчит.

## Свой сервер

Нужен VPS с Docker и домен. Подробная инструкция — **[DEPLOY.md](DEPLOY.md)**:
настройка `.env`, запуск `docker compose`, порты (443/tcp и 443/udp, 4433/udp для
WebTransport, TURN для звонков), обновление и бэкап.

## Разработчикам

```
desktop/        приложение (Wails v3 + Svelte): ПК, веб, Android, iOS
client/core     ядро клиента: MLS-группы, доставка, история, медиа, очередь отправки
client/mls      cgo-мост к mls-rs        mls-ffi/   Rust-обёртка mls-rs
client/store    SQLite клиента           client/transport  HTTP/3 с откатом на HTTP/2
services/       auth, directory, delivery, history, media (connect-go + Postgres/MinIO)
proto/, gen/    protobuf и сгенерированный код
deploy/         docker-compose, Caddy, coturn, скрипты
e2e/            сквозные тесты клиент ↔ сервисы
cmd/kantra      консольный клиент
```

```bash
make up                 # локальный стек: Postgres, MinIO, сервисы, Caddy на https://localhost
make desktop            # приложение для ПК
make desktop-web        # веб-вариант на http://localhost:8090
make android            # APK (нужны Android SDK/NDK)
make test               # тесты, включая e2e (нужен Postgres)
```

Нужны Go (версия из `go.mod`), Rust, Node.js и Docker. Сборки всех платформ и релизы
делает GitHub Actions на каждый пуш в основную ветку.
